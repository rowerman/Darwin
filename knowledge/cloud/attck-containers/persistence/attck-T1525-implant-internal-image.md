# MITRE ATT&CK: T1525 - Implant Internal Image

**技术 ID**: T1525
**战术**: Persistence
**平台**: Containers
**描述**: 攻击者在获得对某个环境的访问权限后，可能会在云或容器镜像中植入恶意代码，以建立持久化访问。亚马逊云服务（AWS）的亚马逊机器镜像（AMIs）、谷歌云平台（GCP）镜像、Azure镜像以及Docker等主流容器运行时都可能被植入恶意程序或留下后门。与上传恶意软件不同，此技术侧重于攻击者在受害者环境内的注册表中植入镜像。根据基础设施的配置方式，如果基础设施配置工具被设定为始终使用最新镜像，这可能会提供持久化访问权限。已有工具被开发出来，用于协助在云容器镜像中植入后门。如果攻击者能够访问被攻陷的AWS实例，并且拥有列出可用容器镜像的权限，他们可能会植入诸如网页shell之类的后门。

**常见方法**:
1. 攻击者可能会在云容器镜像中植入后门，例如在Docker镜像中添加一个包含恶意代码的新层。
2. 攻击者可能会修改已存在的容器镜像，添加一个包含恶意代码的新层。
3. 攻击者可能会在云容器镜像中植入一个包含恶意代码的新镜像。

**检测方法**:
- 将恶意代码植入容器镜像，然后推送至 registry 并在新部署中使用。
- 使用持久性机制创建或修改云虚拟机镜像（亚马逊机器镜像、自定义镜像），然后使用这些植入了（恶意内容的）镜像进行基础设施配置。

**缓解措施**:
1. 定期检查云部署中使用的镜像和容器的完整性，以确保它们未被修改而植入恶意软件。
2. 多家云服务提供商支持内容信任模型，该模型要求容器镜像由可信来源进行签名。
3. 根据最小权限原则，限制与创建和修改平台镜像或容器相关的权限。

**真实案例**:

**案例 1 - Rhino Labs（2019）**:

我们决定自己开发一个，并将其命名为云容器攻击工具（简称 CCAT）。CCAT 的不同之处在于，它通过后门程序和恶意 Docker 镜像，利用容器在云中进行攻击。
