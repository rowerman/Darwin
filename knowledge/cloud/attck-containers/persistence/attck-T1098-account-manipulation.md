# MITRE ATT&CK: T1098 - Account Manipulation

**技术 ID**: T1098
**战术**: Persistence
**平台**: Containers
**描述**: 攻击者可能会操纵账户，以维持和/或提升对受害者系统的访问权限。账户操纵可能包括任何能保留或修改攻击者对已入侵账户访问权限的行为，例如修改凭证或权限组。这些行为还可能包括旨在规避安全策略的账户活动，比如执行迭代式密码更新，以绕过密码有效期策略，延长已泄露凭证的使用时间。要创建或操纵账户，攻击者必须已对系统或域拥有足够的权限。然而，账户操纵也可能导致权限提升，因为相关修改可能会赋予攻击者对额外角色、权限或更高权限的有效账户的访问权。

**常见方法**:
1. 修改已存在账户的凭证，如密码或 SSH 密钥。
2. 添加新账户，分配适当的权限和角色。
3. 变更账户权限，包括添加或删除角色或权限组。

**检测方法**:
- 账户属性变更（例如密码设置、组成员身份、服务主体名称、登录时间）与异常的进程谱系或时间相关联，表明通过有效账户进行的权限提升或持久化操作。
- 使用原生工具或脚本（例如usermod、passwd、groupmod）来提升权限或维持对现有用户的访问权限，这与登录或进程事件相关联。
- 通过dscl、pwpolicy或系统偏好设置命令行工具（sysadminctl）对用户账户进行的修改，这些修改会改变用户组、启用root权限或绕过MDM限制。
- 对SSO/SAML用户属性（例如isAdmin、role、MFA绕过、应用分配）的修改，通常通过命令行界面、应用程序接口或恶意身份提供商应用程序进行。
- 通过API或vSphere客户端添加新用户或更改角色权限（例如，从只读改为管理员），特别是来自非跳转盒IP的操作。
- 在云协作工具（Google Workspace、O365）或文件共享应用中提升角色（例如，编辑→所有者）以维持高级访问权限。

**缓解措施**:
1. 尽可能移除不必要且可能被滥用的认证和授权机制。
2. 对用户账户和特权账户使用多因素认证。
3. 配置访问控制和防火墙，以限制对关键系统和域控制器的访问。大多数云环境支持独立的虚拟私有云（VPC）实例，这些实例能够进一步细分云系统。
4. 通过确保关键服务器的适当安全配置来保护域控制器，以限制可能不必要的协议和服务（如SMB文件共享）的访问。
5. 不要允许域管理员账户用于日常操作，因为这可能会使它们在非特权系统上暴露给潜在的攻击者。
6. 限制对涉及身份验证和/或授权的潜在敏感文件的访问。
7. 确保低权限用户账户没有修改账户或与账户相关的策略的权限。

**真实案例**:

**案例 1 - Sandworm Team （2016）**:

在2016年乌克兰电力攻击期间，沙虫团队在MS-SQL中使用sp_addlinkedsrvlogin命令，在创建的账户与网络中的其他服务器之间建立了链接。
