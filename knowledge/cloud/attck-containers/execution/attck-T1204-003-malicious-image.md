# MITRE ATT&CK: T1204.003 - Malicious Image

**技术 ID**: T1204.003
**战术**: Execution
**平台**: Containers
**描述**: 攻击者可能会依赖用户运行恶意镜像来促成执行。亚马逊云服务（AWS）的亚马逊机器镜像（AMIs）、谷歌云平台（GCP）镜像、Azure镜像以及Docker等流行的容器运行时都可能被植入后门。被植入后门的镜像可能会通过上传恶意软件的方式被上传到公共仓库，然后用户可能会下载该镜像并从中部署实例或容器，却未意识到该镜像是恶意的，从而绕过那些专门用于实现初始访问的技术。这可能会导致恶意代码在实例或容器中执行，例如执行加密货币挖矿的代码。攻击者还可能会以特定方式给镜像命名，以增加用户错误地从该镜像部署实例或容器的可能性（例如：匹配合法资源名称或位置）。

**常见方法**:
1. 攻击者可能会上传包含恶意代码的镜像到公共仓库，例如Docker Hub或Google Container Registry。
2. 攻击者可能会修改已存在的镜像，添加后门或其他恶意组件。
3. 攻击者可能会以特定方式命名镜像，以增加用户错误地从该镜像部署实例或容器的可能性。

**检测方法**:
- 容器（Docker/K8s/containerd）：用户从公共/未知的 registry 拉取不可信的镜像，然后基于该镜像创建/启动容器。启动后不久，容器会生成意外的工具（例如，curl/wget/bash/python），或者建立不符合该命名空间/工作负载常规的出站网络连接。该分析将短时间内且具有一致镜像摘要的镜像创建/
- IAAS（云镜像/虚拟机）：从未经批准或新出现的镜像（AMI/GCP镜像/Azure镜像）启动新的虚拟机/实例。首次启动时，cloud-init/用户数据或嵌入式代理会下载代码、生成系统工具，或开启出站的C2/挖矿流量。该分析将实例/镜像创建→实例启动→ guest内进程/命令执行和/

**缓解措施**:
1. 审核环境中部署的镜像，确保它们不包含任何恶意组件。
2. 利用Docker内容信任等带有数字签名的信任模型，确保在运行时验证特定镜像标签的完整性和发布者。
3. 网络入侵防御系统以及旨在扫描和清除恶意下载内容的系统可用于阻止此类活动。
4. 培训用户，让他们意识到恶意镜像的存在，以及如何避免从这些镜像部署实例和容器。
