# MITRE ATT&CK: T1485 - Data Destruction

**技术 ID**: T1485
**战术**: Impact
**平台**: Containers
**描述**: 攻击者可能会销毁特定系统上的数据和文件，或者在网络上大量销毁数据和文件，以中断系统、服务和网络资源的可用性。数据销毁可能通过覆盖本地和远程驱动器上的文件或数据，使存储的数据无法通过取证技术恢复。常见的操作系统文件删除命令，如del和rm，通常只删除指向文件的指针，而不会擦除文件本身的内容，这使得通过适当的取证方法可以恢复这些文件。这种行为与磁盘内容擦除和磁盘结构擦除不同，因为它销毁的是单个文件，而不是存储磁盘的部分区域或磁盘的逻辑结构。攻击者可能会尝试用随机生成的数据覆盖文件和目录，使其无法恢复。在某些情况下，带有政治倾向的图像文件被用于覆盖数据。在以中断全网可用性为目标的行动中，为了最大限度地对目标组织造成影响，旨在破坏数据的恶意软件可能具备蠕虫般的特性，通过利用诸如有效账户、操作系统凭证窃取和SMB/Windows管理员共享等额外技术在网络中传播。在云环境中，攻击者可能会利用访问权限删除云存储对象、机器镜像、数据库实例以及其他对运营至关重要的基础设施，以损害组织或其客户的利益。同样，他们可能会从本地虚拟化环境中删除虚拟机。

**常见方法**:
1. 攻击者可能会使用操作系统文件删除命令（如del和rm）删除文件或目录。
2. 攻击者可能会用随机生成的数据覆盖文件和目录，使其无法恢复。
3. 攻击者可能会使用带有政治倾向的图像文件覆盖数据，以破坏系统的完整性。

**检测方法**:
- 攻击者会生成命令行工具（例如del、cipher /w、SDelete）或脚本，以递归方式删除或覆盖用户/系统文件。这可能与异常的文件输入输出活动、注册表写入或对关键系统目录的篡改相关联。
- 通过rm -rf、shred、dd或擦除程序二进制文件进行的大规模递归删除或覆盖。可能包括unlink系统调用、已知配置/数据路径的删除，或顺序覆盖模式。
- 通过rm -rf、shred、dd或擦除程序二进制文件进行的大规模递归删除或覆盖。可能包括unlink系统调用、已知配置/数据路径的删除，或顺序覆盖模式。
- 攻击者利用提升的IAM凭证删除关键基础设施：EC2实例、S3存储桶、快照或卷。通常包括带有Delete*或TerminateInstances的批量API调用。
- 攻击者通过调用vim-cmd、删除数据存储内容或清除快照来销毁虚拟磁盘（VMDK）、镜像或虚拟机。
- 容器进程在卷挂载或主机路径内执行破坏性文件操作。包括rm -rf /mnt/volumes/、容器突破以及随后的主机删除尝试。

**缓解措施**:
1. 考虑实施包含定期数据备份程序的IT灾难恢复计划，这些备份可用于恢复组织数据。[51]确保备份存储在系统之外，并能抵御攻击者可能用来获取访问权限、破坏备份以阻止恢复的常见方法。
2. 为云存储资源（如AWS S3存储桶）实施多因素认证（MFA）删除功能，以防止关键数据和基础设施被未授权删除。MFA删除需要额外的认证步骤，这使得攻击者在没有适当凭据的情况下销毁数据变得极为困难。这一额外的安全层通过确保只有经过认证的操作才能不可逆地删除存储或机器镜像，有助于防范云环境中数据销毁带来的影响。
3. 在云环境中，应将修改云存储桶生命周期策略的权限（例如，AWS中的PutLifecycleConfiguration）限制为仅那些有此需求的账户。在AWS环境中，可考虑使用服务控制策略来限制PutBucketLifecycle API调用的使用。

**真实案例**:

**案例 1 -  Sandworm Team（2022）**:
在2022年乌克兰电力攻击期间，沙虫团队在受害者的IT环境系统上部署了CaddyWiper，以删除与OT功能相关的文件，以及映射的驱动器和物理驱动器分区。
