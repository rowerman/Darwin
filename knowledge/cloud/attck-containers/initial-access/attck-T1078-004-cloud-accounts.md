# MITRE ATT&CK: T1078.004 - Cloud Accounts

**技术 ID**: T1078.004
**战术**: Initial Access
**平台**: Containers
**描述**: 云环境中的有效账户可能会让攻击者执行操作，以实现初始访问、持久化、权限提升或防御规避。云账户是组织创建和配置的，供用户、远程支持、服务使用，或用于在云服务提供商或SaaS应用程序中管理资源。云账户可以仅存在于云中；或者，它们可以通过与其他身份源（如Windows Active Directory）的同步或联合，在本地系统和云之间进行混合连接。攻击者可能会通过暴力破解、钓鱼或其他各种方式针对服务账户或用户账户，以获取对环境的访问权限。联合账户或同步账户可能成为攻击者影响本地系统和云环境的途径——例如，利用共享凭据登录远程服务。具有高权限的云账户，无论是联合账户、同步账户还是仅云账户，也可能通过利用基于SaaS的软件部署工具在混合连接的设备上运行命令，从而实现向本地环境的跳转。攻击者可能会在已被攻陷的云账户上创建长期有效的额外云凭据，以在环境中保持持久控制。此类凭据还可用于绕过多因素认证等安全控制措施。云账户还可能通过环境中的各种方式获得临时提升的云访问权限。

**常见方法**:
1. 利用云账户进行初始访问：攻击者可能会通过暴力破解、钓鱼或其他各种方式针对服务账户或用户账户，以获取对环境的访问权限。
2. 利用联合账户或同步账户进行影响：联合账户或同步账户可能成为攻击者影响本地系统和云环境的途径——例如，利用共享凭据登录远程服务。
3. 利用高权限云账户进行跳转：具有高权限的云账户，无论是联合账户、同步账户还是仅云账户，也可能通过利用基于SaaS的软件部署工具在混合连接的设备上运行命令，从而实现向本地环境的跳转。

**检测方法**:
- 检测异常的身份验证活动，例如来自不可能的地理位置的登录，或高权限账户使用旧协议进行的登录。
- 检测云账户在API调用中超出正常范围的使用情况，例如IAM变更或访问从未使用过的服务。
- 检测内部用户对云生产力工具的意外访问或使用（例如，下载大量文件、创建外部共享）。
- 检测偏离典型Microsoft 365或Google Workspace用户配置文件的登录和使用模式。

**缓解措施**:
1. 使用条件访问策略来阻止来自不合规设备或组织定义的IP范围之外的登录。
2. 禁用不支持多因素认证（MFA）的旧版身份验证，转而要求使用现代身份验证协议。
3. 对云账户，尤其是特权账户，使用多因素认证。这可以通过多种形式实现（例如硬件、虚拟、短信），也可以利用管理报告功能进行审计。
4. 确保云账户（尤其是特权账户）在网络上的所有系统中都使用复杂且唯一的密码。密码和访问密钥应定期轮换。这样一来，如果凭据在您不知情的情况下被盗用，可限制凭据被用于访问资源的时间。云服务提供商可能会跟踪访问密钥的使用时长，以帮助审计和识别可能需要轮换的密钥。
5. 定期审查特权云账户的权限级别，以查找那些可能允许攻击者获得广泛访问权限的账户，例如Azure AD中的全局管理员和特权角色管理员。这些审查还应检查是否创建了未经授权的新特权云账户。例如，在Azure AD环境中，配置警报以在账户多天未使用特权角色时发出通知，因为这些角色可能可以被移除。考虑对Azure AD资源使用临时的、即时（JIT）的特权访问，而不是永久分配特权角色。
6. 定期审查用户账户，并移除那些不活跃或不必要的账户。限制用户账户创建额外账户的权限。
7. 应用程序可能会发送推送通知来验证登录，作为多因素认证（MFA）的一种形式。应培训用户仅接受有效的推送通知，并报告可疑的推送通知。

**真实案例**:

**案例 1 - APT28（2021）**:

APT28曾利用具有全局管理员权限的受感染Office 365服务账户从用户收件箱收集电子邮件.
