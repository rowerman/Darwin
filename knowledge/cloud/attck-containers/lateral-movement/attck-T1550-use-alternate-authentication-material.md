# MITRE ATT&CK: T1550 - Use Alternate Authentication Material

**技术 ID**: T1550
**战术**: Lateral Movement
**平台**: Containers
**描述**: 攻击者可能会使用替代认证材料，例如密码哈希、Kerberos票据和应用程序访问令牌，以便在环境中横向移动并绕过正常的系统访问控制。认证过程通常需要有效的身份（例如用户名）以及一个或多个认证因素（例如密码、个人识别码、物理智能卡、令牌生成器等）。当用户或应用程序通过提供有效的身份和所需的认证因素成功认证后，系统会合法生成替代认证材料。替代认证材料也可能在身份创建过程中生成。缓存替代认证材料使系统能够验证身份已成功认证，而无需用户重新输入认证因素。由于替代认证材料必须由系统维护（无论是在内存中还是磁盘上），它可能面临通过凭证访问技术被窃取的风险。通过窃取替代认证材料，攻击者能够绕过系统访问控制，在不知道明文密码或任何额外认证因素的情况下对系统进行认证。

**常见方法**:
1. 攻击者可能会窃取替代认证材料，例如密码哈希、Kerberos票据或应用程序访问令牌。
2. 攻击者可能会使用窃取的替代认证材料来横向移动到环境中的其他系统或服务。
3. 攻击者可能会使用窃取的替代认证材料来绕过正常的系统访问控制，例如使用密码哈希来认证而不是密码。

**检测方法**:
- 使用被盗的Kerberos票据或令牌冒充，导致来自账户的登录会话没有预期的交互式登录事件。
- 在没有相应登录 shell 或 PAM 模块活动的情况下使用的访问令牌或 SSH 密钥，尤其是用于远程执行时。
- 在没有交互式浏览器会话或多因素认证提示的情况下，联合登录中的令牌重放或身份冒充。
- 来自不同地理区域的OAuth访问令牌被异常重用，且没有完整的登录事件。
- 容器进程使用挂载的云凭据或令牌缓存进行身份验证，而无需已知的编排。
- 在没有交互式用户上下文的情况下重用访问令牌以连接到SharePoint或Outlook API。
- 跨实例使用实例元数据令牌，或滥用为不同角色颁发的短期令牌。

**缓解措施**:
1. 在可能的情况下，考虑限制在预期环境之外使用认证材料。
2. 配置Active Directory以阻止某些技术的使用；使用SID筛选等。
3. 考虑实施令牌绑定策略，例如Azure AD令牌保护或OAuth持有证明，这些策略通过加密方式将令牌与密钥绑定。这可以防止在不知道密钥或未持有令牌所绑定设备的情况下使用该令牌。
4. 对系统、权限、不安全软件、不安全配置等进行审计或扫描，以识别潜在漏洞。
5. 为账户设置并执行安全密码策略。
6. 限制不同系统间的凭证重叠，以防止凭证泄露造成的损害，并降低攻击者在系统间进行横向移动的能力。
7. 执行最小权限原则。不允许域用户加入多个系统的本地管理员组。

**真实案例**:

**案例 1 - APT29（2020）**:

在太阳风攻击事件期间，APT29使用伪造的SAML令牌，使攻击者能够冒充用户并绕过多因素认证（MFA），从而让APT29得以访问企业云应用程序和服务。
